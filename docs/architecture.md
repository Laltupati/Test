# System Architecture

QualiVerse AI is architected as an **enterprise-grade, single-container web application** deployed on **Google Cloud Run** and backed by **Google Cloud Firestore**.

## 📦 Single Container Design Pattern

The application uses a **unified multi-stage Docker build (`Dockerfile`)**:

1. **Stage 1 (`frontend-builder`)**:
   - Uses `node:20-alpine`.
   - Installs frontend packages via `npm ci`.
   - Compiles TypeScript and builds production React assets using Vite (`npm run build`).
   - Output directory: `/app/frontend/dist`.

2. **Stage 2 (`backend`)**:
   - Uses `python:3.11-slim`.
   - Installs Python production dependencies (`fastapi`, `uvicorn`, `gunicorn`, `google-cloud-firestore`, `pydantic`).
   - Copies pre-built static assets from Stage 1 into `/app/static`.
   - Runs Gunicorn with Uvicorn workers on port `8080` as a non-root system user (`appuser`).

---

## 🔁 Single Page Application (SPA) Routing & Fallback

FastAPI is configured in `backend/app/main.py` to serve both the JSON API and static frontend assets seamlessly:

- **`/api/v1/*`**: Handled by FastAPI router controllers (`auth.py`, `projects.py`, `admin_projects.py`).
- **`/health`**: Monitored health check endpoint returning system status and Firestore database connectivity.
- **`/assets/*`**: Static JS, CSS, and image assets generated by Vite.
- **`/{full_path:path}`**: Serves static files directly if they exist; otherwise falls back to `static/index.html` to enable client-side React Router navigation (`/admin`, `/login`, `/dashboard`).

## 🗄️ Pluggable Database Abstraction Layer

QualiVerse AI supports dual database backends toggled via environment variables:

```python
# backend/app/core/config.py
class Settings(BaseSettings):
    ENVIRONMENT: str = "development"
    DATABASE_URL: str = f"sqlite:///{DEFAULT_DB_PATH.as_posix()}"
    USE_FIRESTORE: bool = False
    GCP_PROJECT_ID: Optional[str] = "adv-lighthouse-ai-qa-agent"
    FIRESTORE_DATABASE: str = "qualiverse-db"
```

- **Production Mode (`USE_FIRESTORE=true`)**: Interacts directly with Google Cloud Firestore (`qualiverse-db`) using `app/crud/firestore_crud.py`.
- **Local Fallback (`USE_FIRESTORE=false`)**: Interacts with local SQLite database (`qualiverse.db`) using SQLAlchemy ORM (`app/crud/crud_project.py` and `app/crud/crud_user.py`).

## 🛡️ Enterprise Production Topology & Security

Google Cloud Run is an enterprise-grade serverless container platform certified for SOC 1/2/3, ISO/IEC 27001, HIPAA, and PCI-DSS. For enterprise production deployments, the following topology options are recommended and supported:

### 1. Direct Cloud Run Target (`*.run.app`)
- **Use Case:** Development, Staging, and Rapid Internal Previews.
- **Features:** Auto-generated HTTPS, Google-managed SSL certificate, automatic zero-scaling, non-root container security model (`appuser`).

### 2. Enterprise Production Topology (Load Balancer + WAF + Custom Domain)
- **Use Case:** Production Enterprise Deployment (e.g. `qualiverse.kpmg.com`).
- **Components:**
  - **Custom Corporate Domain:** Custom SSL/TLS certificate mapped via Cloud Run Domain Mapping or External Load Balancing.
  - **Cloud Armor Web Application Firewall (WAF):** Protection against DDoS, OWASP Top 10 vulnerabilities, rate limiting, and geo-restriction rules.
  - **Identity-Aware Proxy (IAP) / SAML SSO:** Enforcement of corporate single sign-on before traffic reaches the service.
  - **Security Headers Middleware:** Automatic HTTP Security Headers enforced by FastAPI (`Strict-Transport-Security`, `X-Content-Type-Options: nosniff`, `X-Frame-Options: SAMEORIGIN`, `Referrer-Policy`).
